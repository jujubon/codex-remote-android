# 版本发布

每次更新用户可安装的版本，都同步在维护者的 GitHub 仓库发布 GitHub Release。

1. 同步 Android `versionName`、Windows 包名和 Host 健康接口的版本。Android `versionCode` 必须高于上一版。
2. 运行类型检查和测试，构建 Android APK 与 Windows ZIP。确认 APK 签名兼容覆盖安装，检查两个包的内容和 SHA-256。
3. 提交对应源码并推送到维护者仓库。基于该提交创建 `v<版本号>` 标签。
4. 用该标签发布 GitHub Release，附上 APK、ZIP 和 SHA-256，说明变更、升级方式和已知限制。发布后检查 Release 页面和两个附件。
5. 在发布说明中加上 `<!-- codex-remote:min-host=0.9.23 -->` 格式的兼容版本标记，把示例版本换成新版 App 使用全部功能所需的最低 Windows 版本。

## 0.9.24

- 配套服务同步桌面对话的项目归属。桌面移动对话后，手机列表会自动重新分组。
- 单行输入时对齐附件、文字和发送。多行文字占满上方宽度，按钮并排放在下方。
- 手机收件箱可点开图片看原图。列表用缩略图或图片入口显示，完整文件名和路径可在预览里展开。

Android 可覆盖安装。Windows 升到 0.9.24 后可使用收件箱预览和新的项目归类同步。

## 0.9.23

- 「电脑」页显示当前连接线路。自检分别测量电脑回执、Codex 额度请求和对话列表同步。
- 「待处理」列表和通知可以定位到提问、审批或待处理队列项。桌面实时接口不可用时会提示到电脑处理。
- 「手机收件箱」显示升级后的手机分享和当前对话附件目录里已有的对话附件。选中收件后可使用电脑上已有的文件发送到对话。
- 「版本与更新」显示 Android 和当前连接的 Windows 版本，并可检查 GitHub 更新。

覆盖安装 Android APK。Windows 更新到 0.9.23 后可使用收件箱，无需重启电脑。

## 0.9.22

- Windows 配套可通过 `device-tools.json` 的 `chatAttachmentFolder` 指定聊天附件目录，将手机分享和聊天附件保存在不同文件夹。聊天附件设置在配套服务启动时生效。
- 此次路径变更由 Windows 配套处理，现有 Android 0.9.21 可以继续使用。

## 0.9.21

- 手机上的对话输入框会在本机保存草稿。返回列表或重开 App 后，打开原对话即可继续编辑。
- 电脑确认接受消息或排队后清空草稿。发送失败或未收到回执时保留文字。
- Android 覆盖安装即可使用，现有 0.9.20 Windows 配套兼容。

## 0.9.20

- 在手机使用原来的「新聊天」入口即可启动配套服务管理的新对话。运行时支持引导、排队和停止。完成后可以在 Codex Desktop 打开同一段对话继续。
- 显示会话最近使用的模型。桌面实时设置可用时同步桌面。旧桌面对话走备用接口时，手机选择的模型只用于手机发出的普通消息。
- 精简发送方式说明，统一输入框与两侧按钮的尺寸和对焦样式。手机任务里的结构化异步提问可以选答案或自行撰写。

升级需要 Windows 配套服务和 Android App 都更新。解压 Windows ZIP 后运行 `Enable-Autostart.cmd` 继续使用自动启停，手机覆盖安装同签名 APK 并保留原有连接。

## 0.9.19

- Windows 的「启用自启」改为随 Codex Desktop 启停。登录时仅运行检测程序，打开桌面后才运行配套服务。已由检测程序管理的 Cloudflare 隧道同步启停。
- 解压新版 Windows ZIP 后运行 `Enable-Autostart.cmd`，即可沿用原手机配对。关闭自动启停可运行 `Disable-Autostart.cmd`。这次改动在 Windows 端，Android 0.9.18 可以继续连接。

## 0.9.18

- 手机会显示桌面发出的纯图片消息，历史分页可以补齐之前漏掉的图片。图片源文件仍需保存在电脑上。
- 手机打开桌面对话时，备用接口会检查最新一轮变化，包括电脑后来发送的图片。桌面报告等待用户输入时，手机会保留这个状态。
- 实时接口断开时，手机会说明当前只能排队。答复桌面问题、引导和停止当前轮仍依赖已连接且能操作该对话的桌面实时接口。

覆盖安装新版 Android APK。在 Windows 退出旧配套服务并运行新版 `Start-Tunnel.cmd`，无需重启电脑。

## 0.9.17

- Android 16 及以上在手机提供 Wi-Fi 热点时尝试自动发现已配对的电脑。发现后仍需验证配对并建立直连，失败时继续用固定 HTTPS 域名。
- 电脑需把自己的手机热点设为专用网络，并在 Wi-Fi 网卡上启用可信局域网。旧版 Android 或不允许本地探测的热点仍可尝试手动局域网地址。

手机覆盖安装新版 APK 即可使用热点发现功能。已启用可信局域网的 0.9.15 或 0.9.16 Windows 配套服务也可配合使用。

## 0.9.16

- 跨网投屏区分手机采集和网络传输问题。发送失败后保留最新画面并重试，采集缺帧时尝试恢复原有共享。
- 画面短时中断时，电脑保留最后一帧并暂停翻页。翻页提示区分锁屏、阅读 App、遮挡和键盘。

覆盖安装新版 Android APK。Windows 解压新版，退出旧配套服务后运行新版 `Start-Tunnel.cmd`。无需重启电脑。

## 0.9.15

- 搭配新版 Windows 服务，手机可在可信 Wi-Fi 自动发现已配对的电脑，跟随电脑的局域网地址变化，直连失败时继续使用原有 HTTPS 地址。
- 桌面 IPC 不可用时，手机上传的图片和文件可以作为本地路径随消息发送，运行中可排队到下一轮。内嵌附件、立即引导及停止当前轮仍需要桌面 IPC。

手机覆盖安装新版。Windows 解压新版后，在可信的专用网络上以管理员身份运行一次 `Enable-Trusted-LAN.cmd`，再退出旧配套服务并运行新版 `Start-Tunnel.cmd`。无需重启电脑。手机保留固定域名和配对设置。

## 0.9.14

- 「项目」和「电脑」统一使用浅紫灰底色、白色卡片和紫色操作控件。手机投屏的模式选择、开关与主要按钮沿用同一套配色。
- Android 可覆盖安装。界面更新在手机端生效，原有 Windows 配套服务可继续使用。

## 0.9.13

- 手机对话里，同一轮只显示一次总用时。成功和失败的工具调用默认折叠在执行过程里，展开仍可查看每次的耗时、状态和输出。
- Android 可覆盖安装。此修复在手机端生效，原有 Windows 配套服务可继续使用。

## 0.9.12

- Android 返回前台时先检查原连接。收到回执后沿用连接并补齐近期对话事件，连接失效时自动重连。
- 手机上保留上次收到的模型列表和额度。额度刷新慢时改用 HTTP 补取，超时后可以再次刷新，旧结果仍显示上次读取时间。
- Windows 健康接口和 WebSocket 欢迎消息使用同一个版本号。

Android 可以覆盖安装。Windows 更新时退出旧配套服务，再运行新版 `Start-Tunnel.cmd`，无需重启电脑。

Wi-Fi 和 5G 互切、锁屏后恢复的表现仍需在实际手机和线路上验收。

## 0.9.11

- 手机可直接发起跨网投屏。Windows 打开接收窗口，Android 仍要求用户确认共享。
- 配置可信局域网地址后，App 可在局域网直连与 HTTPS 域名之间切换。
- 「电脑」页统一了投屏选择、按钮与翻页开关，并提供直接分享文件入口。
- 修复历史回放中提问与回答的顺序，加入删除未确认本地消息的入口，默认折叠工具详情。
- 修复桌面原生模式的模型选择和文本发送，改善额度读取及断线后的历史同步。

更新时在 Android 上覆盖安装，在 Windows 上退出旧配套服务并运行新版 `Start-Tunnel.cmd`。

桌面私有 IPC 不可用时，原生发送目前支持普通文字。实机上的 Wi-Fi 与 5G 切换、跨网投屏和 Windows 锁屏场景仍需验收。
